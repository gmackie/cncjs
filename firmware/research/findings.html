Shapeoko: a buildable firmware baseline

Carbide used a shared Grbl image with machine-specific settings applied afterward. Its firmware author explicitly confirms one HEX for three machines and configuration-only changes. The published configuration targets the ATmega328P and uses generic defaults, rather than hard-coding XL travel.

Six configuration changes from stock 1.1f

ChangePractical effect
Line numbers enabledReported line tracking; planner storage drops to 15 blocks, with 14 usable.
Safety-door input enabledThe shared feed-hold input becomes a safety-door input. Software feed hold and the physical door input must be tested separately.
Minimum PWM = 5Minimum nonzero output is 5/255, about 1.96% duty. Stock defaults to 1/255. S0 still turns output off under the saved $30=1000, $31=0 range.
Restore-all mask changedParameter storage is excluded from the “restore all” mask. Coordinate/probe-related stored parameters cannot be assumed cleared by a generic reset procedure.
Z parking enabledConfigured target Z−5 mm; pullout 5 mm at 100 mm/min, then parking at 500 mm/min, subject to runtime conditions. Parking is suppressed in laser mode.
Parking override enabledM56 controls parking behavior; parking is active at initialization in this config.

Evidence: direct diff of Carbide’s published config against the pinned upstream 1.1f config. These are source-level findings, not six independently proven properties of the archived or installed binary.

What this means for your machine

  • DWP611: Grbl cannot adjust its speed dial. A suitable external interface can switch router power; firmware PWM alone does not provide router speed control.
  • J Tech 7 W: Grbl 1.1 already supports laser mode and dynamic M4 power. With the published Carbide config and saved S range, S1 maps to PWM 5/255 and S100 to 30/255 (about 11.76% duty), at 100% override. Duty cycle is not measured optical power. Calibrate low-power behavior during commissioning; no flash is inherently required just to enable laser operation.
  • BitSetter: tool-length measurement and operator sequencing can remain in the CNCjs workflow. A firmware fork is not required merely to orchestrate probing.
  • FabForge and badges: authorization, job release, camera and simulation belong on the Pi/server. Keep the microcontroller focused on timing, motion and tool outputs.
Internal pin mapping and limits

The published config selects the upstream ATmega328P map. At the MCU/Arduino naming level: steps D2/D3/D4; directions D5/D6/D7; stepper disable D8; X/Y/Z limits D9/D10/D12 with variable spindle; PWM D11; spindle direction D13; reset A0; safety door A1; cycle start A2; probe A5.

These are logical MCU assignments, not identified connector positions on your board. Board routing, input conditioning, driver revision, grounding and external interlocks still require physical verification. Firmware safety-door handling is not an independent hardware emergency stop.

Homing is Z first, then X and Y together. Saved Y travel is 850 mm, which remains unverified for your shallow XL. No travel or probe parameters were changed.

Local compilation succeeds

Using pinned upstream 1.1f source plus the unmodified Carbide config, AVR GCC 7.3.0 produces 31,548 bytes of flash and 1,665 bytes of static SRAM. That leaves 383 bytes of the 2 KiB SRAM for stack and remaining runtime needs; it is not a measured worst-case margin.

This build differs from the 31,920-byte archived image. Compiler version/options or source differences can change the result. The original build environment is unknown, so this is a research baseline, not a reproduced vendor release.

Disassembly succeeds, but raw HEX lacks function symbols and includes embedded data. Local ELF symbols cannot be mapped directly onto the archived binary.
